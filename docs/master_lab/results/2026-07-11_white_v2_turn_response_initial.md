# White V2 Turn Response Initial Report

作成日: 2026-07-11

## 結論

- 機械検証は人間チェックへ渡せる段階まで進んだ。ただし現時点は旧 `white_planner` をCPU既定のまま維持する。
- 実験用 `white_v2` として「自ターンの完全手順を複数生成し、各最終盤面に対する相手の完全1ターン応答を比較する」最小構成を実装した。
- 完全情報を使った初期9局では `white_v2` が7勝2敗。その後、相手の実手札と山札順を使わない2仮説平均へ変更した。
- 公平化後の席反転8局ではV2が6勝2敗。V2のペア勝ち2seed、旧AIのペア勝ち0seed、CPU席勝ち2seedだった。
- 候補を広く残すだけの方式、初手カテゴリを均等に残す方式は、速度と勝敗の両方で回帰したため不採用とした。
- 相手の残りカード構成が既知という前提は残るが、実際の手札区分と山札順は応答探索へ渡さない。

## 実装した探索

1. 自ターン内の合法手をビーム探索し、ターン終了までの手順を生成する。
2. 同一最終盤面を除外し、異なる最終盤面を比較する。
3. 上位6案について、相手の非公開領域から2つの決定論的な仮想手札を作る。
4. 各仮想手札で相手側もターン終了まで手順を生成し、サンプルごとの最悪応答を得る。
5. 2つの応答後評価の平均を各案の評価値とし、最大の案を採用する。ログには全サンプル中の最悪値も残す。
6. 採用した手順は状態キーで保持し、レベルアップなどで局面が分岐しない限り同一ターン中に継続する。
7. 既存のターン開始時最大打点チェックはV2探索より前に実行し、確定リーサルを探索幅で落とさない。

V2のログには以下を保存する。

- 採用した自ターン手順
- 自ターン終了時評価
- 相手の最悪応答手順
- 相手応答後評価
- 相手手札モデル、仮説数、全仮説中の最悪評価
- 生成した自ターンプラン数、比較したルート数、相手プラン数

## 不採用にした方式

### 低評価候補の全面開放

攻撃、魔法、召喚、移動、集中の低評価候補まで探索へ入れた。1局が約3-4分へ伸び、seed 995002で敗北、警告も6-11件へ増加した。候補数を増やすだけでは探索の質が上がらず、ビームが低品質手順で埋まったため撤回した。

### 初手カテゴリの均等確保

`前衛召喚`、`後衛召喚`、`敵ユニット攻撃`などを相手応答比較へ1案ずつ残した。seed 995001のV2 Player側が、従来の勝利から敗北へ回帰した。カードヒーローでは同じ攻撃カテゴリでも対象差が重要で、分類が粗すぎたため撤回した。

## レビュー基盤

- ブラウザ対局では、各AI判断直前の復元可能な状態と構造化された判断を `aiDecisionHistory` に保存する。
- コメントの `BAD` / `QUESTION` を、その直前のAI判断へ自動対応付けする。
- `npm run analyze:battle-report -- --report <json>` で、同じ局面を `white_planner` と `white_v2` に再判断させ、V2の自ターン手順と相手応答をMarkdownへ出力する。
- `diff:ai` は比較用判断と実際の対局判断を二重実行しないよう修正し、V2の手順キャッシュを正しく追跡する。

## 既知の制約

1. 実手札区分と山札順は隠したが、相手の残りデッキ構成は既知としている。デッキリスト自体も非公開とする対戦ルールには未対応。
2. 仮想手札は2サンプルだけであり、低確率カードへの期待値はまだ粗い。
3. 相手応答を読む対象は、自ターン終了評価で上位の6案だけ。長期的に優れた準備手が上位6案へ入らない可能性がある。
4. 評価関数は既存White AIを再利用している。探索構造を改善しても、最終盤面評価が誤っていれば悪い長手順を一貫して選ぶ。
5. 思考時間は未調整。270手の対局ではベンチ完了まで数分かかった。今回はユーザー方針どおり強さの構造を先に確認した。

## 次のゲート

次はブラウザのAIを明示的に `White V2` へ切り替えて人間チェックする。既定AIの変更は、その棋譜レビュー後に判断する。

機械側では次の監査を継続できる。

1. 負けseedで、V2が比較した6案に人間的な候補が存在したかを確認する。
2. 候補が存在しない場合だけ候補生成を直し、存在する場合は最終盤面評価を直す。
3. 席偏りseedでは初期手札と先攻1ターン目の差を分離し、V2固有の敗因と混同しない。
4. 強さを維持したまま、状態キャッシュと応答探索の重複を削減して思考時間を調整する。

## 人間チェックで見る項目

- 明確な撃破、レベルアップ、詰め、詰めろを逃していないか
- 盾を攻撃や移動より先に使っていないか
- 盤面制圧より非リーサルのマスター攻撃を優先していないか
- 石を使い切って次ターンの仕事を失っていないか
- 採用手順の説明と実際の一連の行動が一致しているか

ここまで機械検証で絞った後なら、人間は「弱い手を探す」作業ではなく、評価関数では表現できていない局面知識の指摘へ集中できる。
