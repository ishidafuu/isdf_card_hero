# White Backline Summon Improvement Loop Summary

生成: 2026-06-29

## 目的

後列に前衛ユニットを置く問題を、単なる「後列で仕事しない」ではなく「後から引く後衛カードの置き場を潰す」問題として扱う。

今回は、手札だけでなく残り山札の後列仕事カード、非召喚代替、終盤面評価まで含めて改善候補を比較した。

## 追加した監査

- `currentPlayerDeck`
  - 履歴付き master lab で、手番プレイヤーの残り山札を要約する。
- `deck pressure`
  - bad summon 時点で残り山札に後列仕事カードがあるか。
  - 山札上位5枚に後列仕事カードがあるか。
  - 最後の後列枠を潰した時、次以降のドローで配置詰まりが起きやすいか。
- `non-summon alternative`
  - bad summon 局面で、攻撃/ためる/移動/終了が何点差で負けているか。
- `aiSearches`
  - white tuning loop から CPU の検索設定を座席別に渡せるようにした。

## 確認できたこと

baseline 小母数では、bad 3件すべてで残り山札に後列仕事カードがあり、3件すべてで山札上位5枚にも後列仕事カードがあった。

これはユーザー指摘どおり、「今の手札に後衛があるのに置けない」よりも「将来引く後衛の置き場を先に潰している」問題が中心であることを示す。

## 試した候補

| 系統 | 結果 | 判断 |
| --- | --- | --- |
| 後列枠保存ボーナス 80/140/220 | bad が 3 -> 8/8/5 に悪化 | 不採用 |
| 低石限定の非召喚代替 80/140 | bad が 3 -> 9/6 に悪化 | 不採用 |
| 召喚スコアの後列配置補正 | bad が 3 -> 4 に悪化 | 不採用 |
| terminal search width 3/4 | bad が 3 -> 5/5、width4 は勝敗も悪化 | 不採用 |
| 終盤面の後列枠価値 40/55/60/65/80/120 | 65/80/120 は bad を下げたが、中母数で勝敗悪化 | 保留 |

## 有望だったが採用できない候補

`current_back_slot_future_state65` は小母数で `bad 3 -> 1` まで下げ、勝敗も `2-2-0` を維持した。

ただし中母数では以下になった。

| Variant | W-L-D | Bad | Blocked | No Work |
| --- | ---: | ---: | ---: | ---: |
| baseline | 6-2-0 | 19 | 42 | 29 |
| future_state65 | 2-6-0 | 16 | 41 | 30 |

bad は少し減ったが、勝敗が大きく悪化したため採用しない。

## 判断

現時点で default white AI に入れるべき挙動変更はない。

ただし、改善の目処は立った。1手の係数や候補削除ではなく、最終盤面評価に後列枠価値を入れる方向だけが bad を下げた。

問題は、後列枠を大事にしすぎると黒相手のテンポ、白ミラーの盤面圧力まで落ちること。次は単純な後列枠価値ではなく、以下の条件付きにする必要がある。

- 盤面で負けている時は後列枠保存より前衛処理を優先する。
- 相手の次ターン打点源が残る時は後列枠保存を弱める。
- 後列枠を残すことで、次ドロー後に実際に後列仕事カードを置ける見込みがある時だけ評価する。
- 後列枠を残した結果、そのターンの攻撃/撃破/レベルアップ準備を捨てるなら減点する。

## 次にやるべきこと

次は係数を増やすのではなく、`future_state` を条件分解する。

1. `future_state65` で負けた seed を loss audit する。
2. 後列枠保存によって失ったものを分類する。
   - 敵前衛処理を逃した。
   - レベルアップ準備を逃した。
   - マスター詰め/詰めろを逃した。
   - 石を温存したが盤面を返せなかった。
3. 後列枠価値は、盤面有利または互角で、次ドローの後列仕事カードが近く、かつ敵脅威を放置していない時だけ入れる。

この方針なら、ユーザー指摘の「後から後衛を引いたときの置き場」を評価しつつ、白の本筋である盤面制圧を壊しにくい。
